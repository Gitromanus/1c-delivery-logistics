# Дорожная карта: рабочее место логиста (сайт) по задаче из 1С

Задача-источник: 3 блока (матрица районов и лимиты ТС / контроль перегруза на лету / маршрутизация и пакетная печать) + уточнения с голосовой записи (посёлки-районы, «пиление» по улицам, динамика 1-2 машины, геозоны).

Цель этой части: **на сайте реализовать те же правила**, а обмен с 1С — только данными (документы → на сайт, результат → обратно).

## 2. Соответствие требованиям задачи

### Блок 1. Матрица районов и привязка лимитов ТС
- Есть: район↔ТС (`vehicle_zones`), лимит веса (`capacity_kg`).
- Нет:
  - **Объём** (м³) у машин и заявок — считается только вес.
  - Привязка по **улицам/диапазонам домов** внутри района (кейс «посёлок поделен между торговыми по улицам»).

### Блок 2. Контроль перегруза на лету
- Есть: перегруз ловится на сайте при **пересборке рейсов** (`TripBuilder`, сообщение «перегруз +X кг»).
- Нет:
  - **Жёсткая/мягкая проверка при приёмке заявки** через API (при импорте сразу считать накопление на дату+машину и блокировать/предупреждать).
  - Человекочитаемое сообщение в стиле «Машина №2 (район Центр) перегружена. Лимит 3 т, запрошено 3.5 т. Проведение заблокировано».

### Блок 3. Маршрутизация и пакетная печать
- Нет полностью:
  - **Порядок объезда по координатам** (координаты уже есть у заявок — можно выстроить маршрут «ближайший сосед»).
  - **Пакетная печать** ТОРГ-12 / УПД / транспортных накладных в последовательности движения.

## 3. Уточнения из голосового описания (что важно учесть)

1. **Район = населённый пункт** (Новочеркасск, Шахты, Новошахтинск; посёлки Донской, Октябрьский, Молодёжный). Внутри посёлка заявки могут быть от разных торговых, но возит **одна** машина, если мало заявок.
2. **Динамика 1-2 машины на район**: мало заявок → 1 машина закрывает весь район; много → подключается 2-я. Если 1-я перегружена → система предлагает свободную/недогруженную машину рядом; оператор сам решает, куда долить остаток.
3. **Геозоны** (полигоны) рисуются один раз и переиспользуются до правки — это уже реализовано.
4. Объём важен (тоннаж + кубатура), «Гондосы»-машины и т.п.

## 4. План доработок (по приоритету)

### P0 — база (без этого не едет дальше)
- [ ] **Объём в системе**: колонки `volume_cubic` в `vehicles` и `orders`; учёт объёма в расчётах (груз = max(вес/вес_лимит, объём/объём_лимит)).
- [ ] **Контроль загрузки на дату при приёмке**: при POST `/api/orders.php` (и на карте при добавлении) считать сумму веса/объёма по (дата → зона → машина). Режим `warn` (предупреждение) или `block` (жёсткий запрет) — настройка в конфиге.
- [ ] Понятное сообщение блокировки: «Машина N (зона X) перегружена: лимит W кг / V м³, запрошено …».

### P1 — умная логика распределения
- [ ] **Автозакрытие района одной машиной**: при сборке не задействовать 2-ю машину, пока 1-я реально не перегружена (сейчас вторая берёт, только если не влезло).
- [ ] **Подсказки/автодолив**: когда машина перегружена, предложить список свободных/недогруженных машин поблизости (по геопозиции/району); оператор выбирает, куда долить остаток.
- [ ] **Улицы внутри района** (опционально, кейс «пиление посёлка»): таблица `zone_streets` (zone_id, street/диапазон) для более точного попадания заявки в «под-зону» торгового.
- [ ] **Point-in-polygon**: автоматически определять зону заявки по её координатам внутри полигона (дополнительно к ключевым словам). Уже есть координаты + полигоны.

### P2 — маршрутизация и печать
- [ ] **Маршрут по порядку объезда**: внутри рейса сортировать точки по «ближайшему соседу» от базы по lat/lon (координаты уже сохранены). Опционально — подключить Яндекс-маршрутизатор/дороги.
- [ ] **Пакетная печать** документов (ТОРГ-12, УПД, ТН) в порядке маршрута: генерация PDF (шаблон + данные заявки/контрагента/адреса), одна кнопка на рейс.
- [ ] **Обмен сайт → 1С**: передача назад статуса (рейс/машина/порядок/печать), чтобы 1С закрывала документ.

## 5. Что проверить / протестировать перед доработками

- Приём заявки через API корректно накапливает (дата, зона, машина, вес, объём).
- Сценарии из голосового:
  - мало заявок → 1 машина закрывает весь район;
  - много → 2 машины;
  - 1-я перегружена → подсказка свободных машин;
  - обе привязаны, но мало → 2-я не задействована.
- Пограничные случаи: вес ровно = лимит (ок), чуть больше (блок/предупреждение), пустой адрес.
- Объём сейчас нигде не учитывается — подтвердить необходимость и источники данных по объёму из 1С.
- Геозоны: корректное определение попадания точки в полигон.
